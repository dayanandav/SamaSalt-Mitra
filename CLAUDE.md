# SamaSalt-Mitra agent — project notes for AI assistants (AgentFoundry SMART-Code, Claude Code)

Mobile-first web app + Cloudflare Worker agent that tells Indian patients which brands have
EXACTLY the same salt + strength + form as the medicine they photographed, the Jan Aushadhi
(PMBJP) generic and its MRP, and the nearest Jan Aushadhi Kendra. English, Kannada, Hindi.

- `worker/src/normalize.js` — canonical composition key (port of SameSalt's Python pipeline; must stay byte-identical, see parity test)
- `worker/src/tools.js` — agent tools over D1: identify_medicine, find_same_salt, jan_aushadhi_match, nearest_kendra
- `worker/src/vision.js` — read_strip (Workers AI vision) and understand_text
- `worker/src/agent.js` — fixed tool plan + trace; `worker/src/index.js` — API + impact log
- `public/rules.js` — what the page may show (pharmacist list, switch question, Listen); tested in `test/rules.test.mjs`
- `public/strings.js` — ALL user-facing text (en/kn/hi) and the templated answer. Never let a model write prices or safety text.
- `public/app.js`, `public/impact.html`, `public/volunteer.html` — the web app
- Developer mode: only while the address has `?dev=1` (never remembered; the plain address is always the patient app). It shows the impact/volunteer/GitHub/data-import links and flags lookups as test traffic. Hidden for patients.
- `public/dev.html` + `dev.js` — developer data import: PMBI product MRP list CSV → preview diff → apply. `public/pmbi.js` (shared browser + Worker, a port of `data/build_ja.py`'s product parser; must give the same keys) parses in the browser; the Worker's `/api/admin/*` only validates and writes, guarded by the `ADMIN_TOKEN` secret.
- v1.1 Kendra registry: `public/kendra.html`+`kendra.js` (public: how to register by email, standard email from `registrationEmail()` in rules.js, address from the `REGISTRATION_EMAIL` var; online form → prepared email + Send button, nothing saved publicly; "Staff login" → one sign-in, role-based: Registrar registers (email or in person, documents ticked), Reviewer approves/rejects/withdraws/modifies, Admin also adds Reviewers/Registrars, setup key (ADMIN_TOKEN) = system owner who adds Admins; permissions in `can()` in `worker/src/admin.js`; migrations `0004_staff_registration.sql`, `0005_staff_roles.sql`), `public/poster.html`+`poster.js` (printable QR → `/k/<PMBJK code>` → `/?k=`), `worker/src/kendra.js` + migration `0002_kendra_contacts.sql`, admin review on `/kendra#admin` (`public/admin.html`+`admin.js`; sign-in and roles in `worker/src/admin.js`, migration `0003_admin_accounts.sql`: owner signs in with ADMIN_TOKEN and creates reviewer accounts; approving needs three confirmations + a note; every action is logged in `kendra_reviews`). Test site: `npx wrangler deploy --env staging`, see `docs/TESTING.md`. Numbers are shown only after admin approval, and only to test traffic while `KENDRA_REGISTRY = "pilot"` (wrangler.toml) — switch to "public" only after PMBJP agrees. Roadmap and stage status: `docs/ROADMAP.md`.
- v1.2 order requests: the per-visit medicine list keeps pack counts; "Order for pickup" on a Registered Kendra opens an order sheet (`#order` in index.html, `renderOrder` in app.js) that builds a WhatsApp/SMS message (`orderItems`/`orderMessage`/`waLink`/`smsLink` in rules.js; nothing stored). NTI and no-equivalent medicines are left out. Gate: `ORDER_REQUESTS` (pilot on live, public on staging), applied by `markOrders` in index.js.
- v1.3 weak-network mode: `public/sw.js` keeps the patient app's files on the phone (VERSION must equal APP_VERSION; never caches /api or staff pages); offline notice, a check waits for the internet (`pending`, auto re-ask on `online`), last answer kept for the visit (`ss_last`), smaller photos on slow links (`photoSendSize`/`askTimeoutMs`/`savableAnswer` in rules.js).
- v1.3 registered volunteers (PARKED on live: `VOLUNTEER_REGISTRY = "off"`; "on" on staging): public `/volunteer` form prepares an email request (nothing saved); console tab **Volunteers** (`public/vol-admin.js`, started from `showApp` in admin.js) uses `/api/admin/volunteer/*` (`worker/src/volunteers.js`, migration `0006_volunteers.sql`): Registrar registers (ID type only, never its number), Reviewer approves/removes/modifies and sends the link. `/v/SV-XXXXX` → `/?volunteer=SV-XXXXX` (in `run_worker_first`); lookups store only an approved volunteer's code (`lookups.volunteer`).
- v2.0 WhatsApp bot (`WHATSAPP_BOT`: off on live, on on staging): `worker/src/whatsapp.js` (Meta Cloud API webhook `/api/wa/webhook`, conversation, chat memory keyed by HMAC of the number, 24 h, DELETE), `worker/src/watext.js` (reply text from composeAnswer + `wa*` strings), short order link `/o/<Kendra>/<PMBJP code>` (in `run_worker_first`; never for NTI), simulator `/wa-sim` → `/api/wa/simulate` (test traffic only). Migration `0007_whatsapp.sql`. Secrets WA_TOKEN, WA_PHONE_ID, WA_APP_SECRET, WA_VERIFY_TOKEN, WA_HASH_KEY.
- v2.0.1 Chat: floating **Chat** button (`#chatFab`, home + answers) → `#chatView` (app.js → `/api/chat`, `APP_CHAT` off on live / on on staging, logged as mode `chat`), chips (scan / Kendra / language / clear), conversation kept for the visit (`ss_chat`, `ss_chat_log`, no photos); WhatsApp icon in the chat header (`wa.me/<WA_BOT_NUMBER>`, only when the bot is on and the number set; from `/api/health`). `public/chat.js` is the chat box shared with `/wa-sim`.
- v2.0.2 hardening: `worker/src/limits.js` — per-address limits (Cloudflare Rate Limiting bindings `LIMIT_CHECK` on /api/ask, /api/chat, /api/feedback, /api/wa/simulate; `LIMIT_LOGIN` on /api/admin/login; the IP is only a counter key, never stored) → 429 "busy" (`tooMany`), and the daily photo cap `DAILY_PHOTO_LIMIT` → "type the name". `public/privacy.html` (en/kn/hi privacy + disclaimer, linked from every footer). Own domain: `CANONICAL_HOST` + `routes` (docs/DOMAIN.md); `canonicalRedirect` in index.js, app.js moves the page.
- v2.0.3 NPPA ceiling prices: `public/ceiling.js` (shared browser + Worker; NPPA rows → the same composition keys via pmbi.js `parseGeneric`), `/dev` card → `/api/admin/ceiling/current|apply` (system owner), migration `0008_ceiling_prices.sql`, agent step `ceiling_price` (`ceilingPrice` in tools.js; skipped for NTI and until `ceiling_list_date` is set), app card "Government maximum price (NPPA)" + `waCeiling` line. Never compares the old brand MRPs against it (no "overpriced" flags on stale data); the patient checks the MRP on the strip.
- v2.0.4 patient features: **Share** (`shareText` in rules.js; NTI shares the warning only), **Add to home screen** (`beforeinstallprompt`, `#installBar`, "Not now" = `ss_install_no`), **Scan a prescription** (`#rxBtn` → `/api/prescription` → `readPrescriptionAgent` in agent.js + prompt `read_prescription.md`: names only, matched with identify_medicine, nothing priced until tapped; counts towards `DAILY_PHOTO_LIMIT` via `rx_reads_<day>` in meta), **Kendras by distance** (`pin_locations`, migration 0010 (0009 unused: stock reports were removed), loaded by `data/build_pins.mjs` from India Post's pincode directory, which also sets `kendras.lat/lng` = PIN centre; `nearestKendra` sorts by km for a known PIN or "Use my location" (rounded to ~1 km, not stored); shown as "≈ X km").
- v2.0.5 operations: `.github/workflows/test.yml` (all tests on push/PR), `.github/workflows/monitor.yml` (live check every 3 h: home, /api/health, lists loaded, `usage.photo_reads` < 80% of `photo_cap`; failure = GitHub email), `tools/backup.mjs` (wrangler d1 export → `backups/`, gitignored, keeps 12), `docs/OPERATIONS.md` (Time Travel restore, free limits). `/impact?month=YYYY-MM` + CSV / print report. - v2.0.8 S3.10/S3.11: photo tip under Take a photo (`.scan-tip`, `photoTypeTip` after 2 unread photos per visit, `ss_unread`); typed salt + strength → `saltChoices` (tools.js; brand keys searched as text in keys.json, never parsed; Jan Aushadhi first; choices only, each verified). - v2.0.9 P2/P3/P5: "Is the quality the same?" under the Jan Aushadhi card (`trustHtml` in app.js, text `jaTrust`; never for NTI); "Show this to your doctor" on the pharmacist list (`doctorNote` in rules.js → dialog `#doctor`, English for the doctor, Print via `body.print-doctor`, Share; NTI and unlisted left out; no prices, no dosage); demand by area on /impact (`demand_by_area` in handleImpact: JA medicines per `pin3`, ≥ `DEMAND_MIN` = 3 checks, real traffic, not 'wrong'). P2/P3 wording: as drafted, made live by the owner 23 Nov 2026. Tests: `test/doctor-demand.test.mjs`.
- `data/` — build D1 seed SQL from SameSalt's DB and the official PMBJP lists
- Brand medicines are static files, not D1 rows: `node data/build_meds.mjs --db ../samesalt/assets/samesalt.db` writes `public/meds/` (gitignored, ~10.5k files, uploaded by `wrangler deploy`). `worker/src/medstore.js` reads them (D1 `medicines` table is the fallback, used by tests); `test/medstore.test.mjs` proves both give identical results. Reason: free D1 allows 100k rows written/day; this list needs ~740k.
- `test/` — all tests: `node tools/test-lock.mjs run` (every JS test + `python test/test_build_ja.py` + the test lock). `test/core.contract.test.mjs` = the core design rules (languages and {slots}, no dose advice, prices only from data, same salt/strength/form/release, never-switch list only grows, no personal data in `lookups`, live switches).
- **Test lock (owner's rule):** `.githooks/pre-commit` (enable per clone: `git config core.hooksPath .githooks`) runs `node tools/test-lock.mjs run` and blocks the commit if a test fails or a test file differs from `test/APPROVED.json`; CI checks the lock too. An AI assistant must NEVER change, add or remove a test, nor run `test-lock.mjs approve`, to make a change pass: report the break and let the owner decide. Only the owner approves (`node tools/test-lock.mjs approve --yes` after `git diff -- test/`). Never commit with `--no-verify`.
- `evals/` — `node evals/run_evals.mjs` (writes AF run JSONL to `.codenow/runs/`); search test set `node evals/run_search_evals.mjs` (cases built from the data by `evals/build_search_cases.mjs`; must stay at 0 wrong matches — run it after any matching change)

Rules: same salt + same strength + same form + same release only. Never give dosage advice. Narrow-
therapeutic-index salts never get a "switch" suggestion. Impact log stores no personal data.
